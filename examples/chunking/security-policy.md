# Account security policy

## Verifying identity

Before changing anything on a customer's account, the agent must confirm that the person writing in is an owner or admin of the workspace. Confirmation means the request comes from the email address on the account, or the customer answers the security question stored in the admin panel, or the customer replies from a verified email to a code the agent sends. A matching name is not enough. A matching company domain is not enough either, because former employees often keep access to old mailboxes for weeks after they leave. If none of the three checks pass, the agent replies that the change cannot be made and explains how an existing owner can make it instead. Agents must never read out, email, or confirm any part of a stored password, recovery code, or API key, not even the last four characters. Agents must never disable two-factor authentication on request; the customer has to use a recovery code, or an existing owner has to remove and re-invite the user. If a customer claims to be locked out of every owner account in the workspace, the ticket goes to the security team with the workspace id and a short summary, and the agent tells the customer that the security team will contact them within one business day. Requests that mention legal action, law enforcement, or a court order are never handled by support; they are forwarded to the legal team unchanged and the agent does not reply with any account details. Agents who suspect an account takeover, for example a sudden change of owner email followed by a request to export all data, freeze the export and escalate to security straight away, even if the request seems to come from a verified address. Every identity check, passed or failed, is recorded as an internal note on the ticket, so that a later reviewer can see which check was used and why the change was or was not made. Agents also must not change the billing email, the workspace name, or the list of owners on the strength of a phone call, because caller id is easy to fake and calls leave no written trail. When a verified owner asks to add a new owner, the agent sends the invite to the new person's address and never shares an invite link in the ticket thread itself. If the customer pushes back on any of these checks, the agent explains that the checks protect the customer's own data, and does not make an exception, even for large accounts or urgent requests. Exceptions are only possible with written approval from the security team, and that approval is pasted into the ticket as an internal note before the change is made.

## Reporting a breach

If an agent believes customer data was exposed, they stop work on the ticket and page the on-call security engineer. They do not tell the customer anything about a possible breach until security has confirmed what happened.
